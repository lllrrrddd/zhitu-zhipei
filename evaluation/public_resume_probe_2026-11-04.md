# 公开合成简历试测（2026-11-04）

## 样本与方法

从 [SyntheticResumeData](https://github.com/jijunhao/SyntheticResumeData) 的提交 `3ecd09129f65955e743aacf67f2785fcee10d461` 选取编号 1、2、3、100、500、1000 的六份合成 PDF 和对应 JSON 标注。项目声明这些内容为合成简历，许可证为 Apache-2.0；本地保留了 LICENSE 和 README。这里只取少量样本，没有下载全库，也没有使用真实求职者资料。

对六份 PDF 运行现有 `document_text.extract_document_text` 和 `profile_text_parser.parse_profile_text`；另对 1、2 号 PDF 调用应用的 `/api/profile/parse-text`，启用本地 Qwen3.5 4B。该接口只返回草稿，没有保存到用户资料。原始逐例结果见 `public_resume_parse_2026-11-04.json` 和 `public_resume_ai_2026-11-04.json`，复测脚本在 `scripts/`。

## 观察结果

| 检查项 | 结果 |
| --- | --- |
| PDF 文字提取 | 6/6 有文字；每份约 608～1217 字符 |
| 本地规则识别姓名 | 初测 3/6；修复 PDF 文本顺序问题后 5/6，与标注一致；剩余 1 份提示人工填写 |
| 本地规则教育条数 | 初测 1/6；第二轮修复后 3/6 与标注条数一致 |
| 本地规则工作经历条数 | 初测 3/6；第二轮修复后 2/6 与标注条数一致。100 号原来将“掌握技能”误当工作，移除该假阳性后条数命中下降 |
| 标注学校名称在文本/学校字段中出现 | 9 个非空标注中，PDF 文本包含 9 个；解析学校字段包含 7 个 |
| 标注公司名称在文本/公司字段中出现 | 9 个非空标注中，PDF 文本包含 7 个；解析公司字段包含 3 个 |
| AI 识别 1 号 | 约 87 秒；姓名、两段教育与标注一致，一段工作经历被拆成两段 |
| AI 识别 2 号 | 约 102 秒；姓名一致，教育返回两段而标注为一段，常规工作经历字段为空而标注为三段 |

这些是六例诊断结果，不是总体准确率。“名称出现”仅做去空白后的子串检查，不代表字段边界、归属或内容正确。只按条数比较，也无法证明字段内容正确。2 号标注的两家非空公司在 PDF 文字层均未出现，不能归责于结构解析；100、500、1000 号的公司名称出现于文本但未落入公司字段。1 号标注里年龄与出生年月自相矛盾，说明公开合成标注也需要人工抽查。

## 已完成的解析修复

PDF 文字层会把页眉姓名排到教育、工作正文之后。姓名解析现能在全文中找唯一的独立短姓名，并在候选不唯一时留给用户确认；无标签的六字正文不再直接当姓名。六例姓名命中由 3/6 提高到 5/6。

第二轮将日期开头、句号结尾的学历行识别为新条目；将特殊项目符号开头的“担任学生会”内容保留在当前学历条目中；问答式简历的工作、校园、技能问题会切换分区。“掌握技能”“所获嘉奖”“所持证书”等常见标题不再继续污染前面的工作分区。教育标题存在但未形成条目时显示人工核对提示。教育条数与标注一致的样本由 1/6 提高到 3/6。48 项相关解析测试通过。逐例 JSON 已复测。

3 号问答式简历现在能识别工作分区，但仍把一段创业项目算作第三段工作，标注为两段；100 号把基本资料和职位当学历，且 PDF 文字层中未见明确的工作条目；500 号的教育内容不准确，1000 号的 PDF 标题与正文错序导致漏学历。1 号虽然两段教育条数正确，学校、专业和学位字段仍有混入。它们仍需人工逐字段核对，不能仅按条数评估质量。

## 对产品的直接影响

1. 文件能提取文字，不代表可以自动填好画像。当前姓名、学历、经历的错误足以影响岗位硬门槛判断。
2. AI 返回“字段和来源校验通过”也不代表结构正确。需要分区核对、重复经历检测、低置信度标记和人工确认。
3. CPU 模型单份约需 1.5 分钟；批量简历与岗位测试要有异步进度、缓存和可复现的离线评测。
4. 这六例覆盖一些版式，但研究生目标场景只有少量相关案例。下一批应重点加入不同专业的研究生简历，以及论文、科研项目、实习和就业意向的标注。
