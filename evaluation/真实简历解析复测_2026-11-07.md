# 真实简历解析复测（2026-11-07）

## 这份文档回答什么

用 12 份真实授权的简历文件（含扫描件与网页打印件）跑一遍当前解析链路，量出**字段级**的正确率，并按暴露的问题改了解析器、给出改动前后的对比。原始文件只在本机 `samples/private/`（已被 `.gitignore` 排除），本文不含任何姓名、电话、邮箱、公司原名或个人经历原文。

**边界**：样本来自组内授权，由我一人标注与核对，不是独立盲审；12 份也不足以代表真实分布。这里的数字只说明"这批样本上的字段抽取表现"，**不能作为产品准确率**，也不能对外表述为"识别率 X%"。

## 方法

| 项 | 说明 |
| --- | --- |
| 入口 | 后端 `/api/profile/parse-text` 的同一套函数：`extract_documents_text` → `parse_profile_text` |
| 提取 | PDF 走 pypdf（与后端文档通路一致）；DOCX 走 python-docx 通路 |
| 样本编号 | S01–S12（与文件名的对应关系只在本机保留） |
| 判定 | 姓名/学校按归一后**完全相等**判定；教育条数按"条目个数是否等于原文中的教育段数"判定 |
| 复测方式 | 同一批文件、同一台机器、同一份代码，改前改后各跑一遍 |

## 结果

| 指标 | 改前 | 改后 |
| --- | --- | --- |
| 能进入解析的文件 | 8/12 | 8/12 |
| 姓名正确 | 2/8 | **7/8** |
| 首个教育条目的学校正确 | 7/8 | 7/8 |
| 教育条目个数正确 | 4/8 | **8/8** |
| 技能列表含句子残片的文件 | 6/8 | 1/8 |
| 单份文件技能条数中位数 | 17 | 14 |
| 单份文件技能条数最大值 | 200 | 200（见"未解决"） |

改前的三类典型错误（已全部消除）：

1. **姓名取成了版面标签**：两份"考研成绩单式"简历的姓名栏显示为 `初试成绩`；一份 DOCX 因为标签被撑开（`姓　　名：`）而完全识别不到；两份把三个字的姓名截成两个（`王 宇 松` → `王`、`贾文 杰` → `贾文`）。
2. **教育条目按重复次数翻倍**：一份 DOCX 的"教育背景"因为文本层重复 4 遍，输出 4 条同校记录；另一份输出 3 条同校记录。
3. **技能被句子碎片污染**：`保障系统稳定。`、`能够独立开发自动化运维工具`、`2026.01-2026.04`、`项目经历 1`、`技术栈：Java 17…` 都曾作为"技能"进入列表——它们会直接参与岗位匹配的技能命中，属于"看起来有证据、其实没有"的错误。

## 这一轮改了什么

| 问题 | 改法 | 位置 |
| --- | --- | --- |
| 文本层重复 2–4 遍 | 行内自我重复折叠 + 相邻同文行只留一条（跨分区不合并，避免误删两个分区各自的"本科"） | `profile_parser/line_dedupe.py`、`normalization._normalize_lines` |
| 标签被撑开（`姓    名`、`籍　　贯`） | 中文标签按字匹配并允许字间空白；英文标签保持原样（`E-mail` 不能被拆） | `basic_fields._label_regex_source` |
| 多个字段被成分一行（`姓名：李四籍　　贯：…`） | 标签边界不再要求前一字符是空白，第二个标签也能被识别，姓名不再吞掉整行 | `basic_fields._label_matches_pattern` |
| 姓名字间加空格 | 整行或单个 token 合并后为 2–3 字时认定为姓名（`郑州 大学` 合并后 4 字，不认） | `basic_fields._collapse_spaced_chinese_name` |
| 考研成绩单开头的多列表头 | 新增"整行都是 2–6 字纯汉字、≥4 列、无电话/邮箱/数字"判定，跳过该行 | `basic_fields._looks_like_column_header` |
| 同校教育条目重复 | 按学校名归并（`华南师范大学（211）` 与 `华南师范大学` 视为同一所），只在专业/学历不矛盾时合并，保留信息更全的一条 | `profile_parser/entry_dedupe.py` |
| 论文/奖项/报考信息被当成学校 | 学校字段超过 24 字或命中论文、奖学金、课程明细、报考等标记时整条丢弃 | `section_parsers._EDUCATION_NOISE_MARKERS` |
| 中文校名/专业名里夹空格 | 纯中文值去掉内部空白（含拉丁字母的值不动，避免 `New York University` 粘成一词） | `section_parsers._collapse_cjk_spaces` |
| `技术栈：…` 被当成技能分区标题 | 未带编号的技术栈/技术方案/开发环境/主要工作等标签不再开启新分区，留在项目条目内 | `normalization._DETAIL_LABEL_HEADS` |
| 技能区里的句子残片 | 含句末标点、含冒号、日期开头、动词短语开头、超过 32 字的一律不收 | `skill_fields._looks_like_skill_fragment` |
| 整篇网页文章被当成简历正文 | 首个分区标题前有 800 字以上、含两段长句、且没有任何电话/邮箱/"姓名"时跳过该前缀，并在 warnings 里告知用户 | `normalization._trim_non_resume_prefix` |

新增测试：`tests/test_profile_resume_noise.py`（9 项，用合成文本复现上述版面，不含真实数据）。既有解析测试 65 项全部通过。

1. **兼容字形**：PDF 把「大」写成康熙部首 `⼤`（U+2F24），"大学"后缀匹配不上，整个教育条目被拆成"学校＝江汉⼤学--数字媒体技术、专业＝(本科)"。现在只对 CJK 部首/兼容表意区做单字 NFKC，全角标点保持原样。
2. **`--` 与 `〜`**：`江汉大学 -- 数字媒体技术`、`2022-09 〜 2026-06` 之前都不认，日期残留在学校名里。双横线与波浪线现已并进条目分隔符与日期区间分隔符。
3. **课程明细里的成绩**：`Python（95/100）`、`GPA(3.49/4.0)` 被 `/` 切开后当成学校名。现在学校/专业命中成绩碎片就丢弃该条；`数字媒体技术（本科）` 这类"专业挂学历"会把学历拆回学位字段。

### 仍然存在的问题（如实记录）

- **混排网页打印件**：`简历(1)` 与 `简历2/3/4`（同一份文档的三次导出）仍会把正文文章解析成技能。这一轮加了"尾部文章裁剪"（连续 3 行 40 字以上长句、无日期无项目符号、尾部 ≥1500 字且不含分区标题才剪），`简历(1)` 的技能从 200 条降到 104 条、姓名不再被误取成 `{`；另外三份因正文被 PDF 折行（行尾没有句号）没有触发裁剪，仍是 200 条触顶。

## 2026-11-08 第三轮：聊天记录导出件与校名后缀

第二轮之后剩下的三类问题（混排聊天记录导出、校名带专业后缀、项目要点当技能）这一轮处理：

| 指标 | 第二轮 | 第三轮 |
| --- | --- | --- |
| 姓名正确 | 9/12 | **12/12** |
| 首个教育条目学校正确 | 10/12 | 10/12 |
| 教育条目个数正确 | 9/12 | **11/12** |
| 技能条数（混排文件） | 91 / 200×3 | **2 / 0 / 26 / 0** |

改了什么：

1. **重复简历裁剪**：`简历2/3/4` 其实是"把简历贴给 AI"的聊天记录导出——同一份简历连标题一起被粘贴 3–5 遍。判据是**同一个分区标题出现 ≥3 次**（正常简历每个标题一次），从第二份副本开始剪掉并告警。这一刀把这三份文件的技能从 200 条（触顶截断）降到 0–26 条，姓名也从正文残片变回空值/正确值。
2. **校名后缀合并**：`中北大学 软件工程-网络与信息安全方向（本科）` 之前被切成"学校＝中北大学软件工程"，现在学校＝中北大学、专业＝软件工程-网络与信息安全方向、学历＝本科（该文件三个字段全部正确了）。
3. **技能碎片再收一档**：`完善支付安全 ...`、`RAG 检索优化 …` 这类被截断的项目要点、以及 `主要工作`/`项目职责` 这类标签不再进技能栏；技能 ≥60 条时给出"文件里可能混入正文或聊天记录，建议只上传简历正文"的告警。

### 仍未解决（如实记录）

- `简历2`、`简历4` 现在**没有教育条目**：这两份文件的真实学历行落在后面那份"模型复述副本"里，只保留第一份时一并被剪；`简历4` 的首个学校还取到了另一所（杭州电子科技大学）。这类"聊天记录里夹简历"的导出件，正确做法是在入口就让用户改传简历正文——我们已经给出告警，但没法在不误伤正常简历的前提下把它解析干净。
- `王宇松简历`、`王璐凯简历` 技能仍为 0 条：研究型简历没有独立技能区，技能要从项目描述里回抽，属于另一个功能（需要标注后再做）。
- 学校正确率停在 10/12：除上面两份外，`吴晨-简历.pdf` 已修好，剩下的是同一批聊天记录文件。

一句话总结：**正常简历（8 份）现在字段全对；聊天记录导出件（4 份，实为 2 份文档）能进解析、能给出可用告警，但不能保证解析干净。**

## 2026-11-09 第四轮：研究型简历的技能回抽

前几轮记录的两个"技能 0 条"样本（王宇松、王璐凯）都出在**研究型简历**：它们没有
"专业技能"这一节，能力全写在项目描述里（"使用 HPLC 与电化学工作站完成检测"、
"UE5 NPR 渲染框架搭建"）。解析器只认技能区，于是这两份画像进岗位匹配时技能项恒为 0。

做法（`profile_parser/skill_backfill.py`）：

- 技能词表抽成共享模块 `services/skill_lexicon.py`（匹配与解析共用一份，避免漂移），
  并补一层科研/工程类能力词：电化学、色谱分析、光谱分析、质谱分析、材料制备、
  材料表征、实验设计、文献调研、数据建模、工艺放大、三维渲染、虚拟现实、交互原型。
- **只在不缺技能时回抽**：原有技能 ≥3 条就一个字段都不加（避免把项目描述塞进技能栏）。
- **只认词表**，不做自由切词，宁可少抽。
- 回抽会写一条告警："简历里没有独立的技能区，已从项目/经历描述里回抽 N 条能力词，请核对"。

实测：

| 样本 | 改前 | 改后 |
| --- | --- | --- |
| 王宇松（应用化学，4 段科研项目） | 0 条 | 5 条：数据分析、电化学、材料制备、实验设计、文献调研 |
| 王璐凯（数字媒体，UE5/VR 项目） | 0 条 | 2 条：C/C++、三维渲染 |
| 吴晨（运维，有技能区，19 条） | 19 条 | 19 条（不动，符合"够数就不回抽"） |

新增 `tests/test_skill_backfill.py`（4 项）：词表合并、无技能区时回抽、有技能区不动、
无可匹配文本时不改动。

## 2026-11-09 第四轮：emoji 标题、无校名学历行、技能拆分残片

第三轮之后剩下的两类问题（聊天导出件缺教育条目、混排打印件技能仍脏）这一轮定位到
**同一个根因的两个面**：分区标题前带 emoji（`🎓教育背景`、`⚙专业技能`、`💼实习经历`）
时认不出标题，于是整段结构错位——学校取到后面"复述副本"里的、技能把项目名和句子
残片一起收进来。

| 指标 | 第三轮 | 第四轮 |
| --- | --- | --- |
| 教育条目个数正确 | 11/12 | **12/12** |
| 首个学校正确 | 10/12 | **11/12**（剩下那份原文没有学校名） |
| 混排件技能条数 | 2 / 0 / 26 / 0 | **5 / 16 / 2 / 4**，且无半边括号残片、无证书成绩 |
| 正常件（8 份）姓名 / 学校 | 8/8 / 8/8 | 8/8 / 8/8（未动） |

改了什么：

1. **行首装饰符号剥离**：`_clean_line` 去掉行首 emoji / 箭头 / 勾叉 / 几何符号，
   `🎓教育背景` 从此能认成教育分区。这一刀同时修好了"学校取到后面副本"和
   "技能混进项目名"——两者都是分区错位的后果。
2. **聊天导出件的简历起点**：前缀裁剪原本只认"第一个分区标题"，把 `个人简历` 之后的
   表头（出生年月、求职意向、学历行）当正文文章剪掉。现在若在第一个分区标题之前
   见到一行独立的 `个人简历` / `简历` / `Resume`，就以它为起点（取最后一处，
   前面可能还有"帮我看看这份简历"之类的引用）。
3. **无校名学历行**：`计算机科学与技术 | 本科 2023.09 - 至今` 这类行原文就丢了学校列。
   以前整条丢弃（教育条目 0 条），现在保留成"学校空、专业与学历正确"的条目，
   并告警「教育条目里没有学校名，请在核对页补上」。
   - 判据收紧到 `len(school) <= 24`：放宽后会把「论文标题」当成专业名救回来，
     王宇松那份立刻多出一条假教育条目（本轮实测踩到，已修）。
4. **技能拆分的括号保护**：`掌握集合、并发（线程池、锁、AQS）、JVM 内存与 GC`
   按顿号一刀切会产出 `并发（线程池` / `锁` / `AQS）` 三条残片。现在先把括号内的
   分隔符换成占位符再拆，拆完还原；配合"括号不配对即碎片""单字汉字即碎片"
   "带分数的语言证书（雅思 7.0 / CET-6 585 分）不算技能"三条过滤。

### 仍未解决（如实记录）

- **4 份聊天导出件的姓名仍为空**：它们的原文里确实没有姓名行（只有"个人简历"标题），
  不是解析漏读。
- **`简历2` 的学校仍为空**：该文件第一份简历的学历行原文就没有学校名（真实学校只出现在
  后面被剪掉的"复述副本"里）。按"宁可留空+告警，也不从别处借"的原则处理。

- `简历.pdf` 技能 31 条、`吴晨` 17–19 条仍偏多，但都是真实条目，不再过滤。

## 2026-11-09 第五轮：PDF 硬折行合并

第四轮之后只剩一类问题：PDF 文本层按版面宽度硬折行，一句完整的话被切成两行，技能栏里
就出现 `可通过日` / `志分析` 这样的残片（`吴晨-简历.pdf`）。这一轮在归一化阶段加了
**折行续接**：满足"上一行明显没写完"时把下一行接回去。
