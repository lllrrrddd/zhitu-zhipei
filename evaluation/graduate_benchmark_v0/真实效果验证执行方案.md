# 职途智配真实效果验证执行方案

这份方案用于下一轮小范围验证。当前的 5 份虚构画像和 14 条岗位参与了规则设计，只能做演示与回归，不能当作独立准确率。团队成员信息暂不填写。

## 先准备什么

1. 找两位**没有参与规则编写**的复核者，分别填写 `review_forms/reviewer_a.md`、`reviewer_b.md`。填写前不要看 `labels.json` 或对方的结果。记录分歧、来源页面日期和最终裁决；无法判断就保留“未知”。
2. 另找 20～30 条**未用于调规则**的研究生相关岗位，覆盖至少三个专业方向和明确不合适的反例。记录原始 HTTPS 链接、查阅日期、招聘是否仍开放、学历与届别条款。来源失效的岗位单列，不补造原文。
3. 邀请少量真实研究生和至少一位就业指导教师试用。先说明任务、数据用途、记录范围和退出方式；获得明确同意后再使用其材料。允许只用虚构画像完成任务，拒绝提供简历不影响试用。

## 每位试用者怎么做

观察者准备一份授权简历或虚构画像、两条与其方向有关和一条明显不合适的岗位原文。试用者独立完成 `真实试用记录模板.md` 的五项任务；观察者只记录完成情况、用时、提示次数和错误类型，不替试用者修改结果。每个岗位先让试用者核对来源、开放状态与草稿字段，再查看系统排序；这样不会把系统输出当作标准答案。

试用者可在页面下载建议反馈 JSON；只有试用者检查并主动交付后，观察者才收集。原始简历、姓名、电话、邮箱、反馈 JSON 和含个人信息的截图只放在本机 `private_trials/`，该目录已被 Git 忽略。公开报告只写代号、汇总数量和经检查的匿名错误案例。

## 如何判定结果

| 指标 | 分子 / 分母 | 必须同时记录 |
| --- | --- | --- |
| 任务完成率 | 无观察者代做而完成的任务数 / 实际尝试任务数 | 每项用时、提示次数、放弃原因 |
| 简历字段正确率 | 经原文核对正确的字段数 / 抽查字段数 | 姓名、学历、专业、经历、能力分别统计；空值单列 |
| 岗位草稿字段正确率 | 经招聘原文核对正确的候选字段数 / 抽查候选字段数 | 单位、岗位、城市、学历、届别、专业、能力、来源、截止状态分别统计；漏提和误提单列 |
| 硬门槛错误 | 错误阻断、错误放行、把未知当确定的岗位数 | 每个错误附来源短片段与人工裁决；分母为人工可判定岗位数 |
| 证据正确率 | 真实且支持结论的命中证据数 / 抽查命中证据数 | 引文真实但不支持结论也算错 |
| Top-5 排序 | 在独立裁决的保留集上计算 Precision@5、Recall@5、NDCG@10 | 只用状态已核实且标签已裁决的岗位；报告样本数和空结果 |

预先保留所有失败案例；不要只挑成功页面截图。对每个错误标注发生在简历解析、岗位草稿、硬门槛、方向匹配、证据、来源状态或界面操作的哪一步。两位复核者意见不一致且无法裁决的岗位不进入准确率分母，在报告中单列数量。

## 完成判据

试用完成后汇总：实际人数、专业分布、岗位数与来源核查日期、各指标分子分母、最严重的三类错误、修复前后的同集对比，以及仍未知的条件。只有出现这份可复核报告，才能说“已完成真实效果验证”；在此之前只能说“原型可运行、验证材料已准备”。
