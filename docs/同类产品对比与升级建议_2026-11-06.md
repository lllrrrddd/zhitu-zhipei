# 职途智配：同类产品对比与升级建议（2026-11-06）

## 对比范围

以下选取几款常见的简历与求职工具，依据各产品官方功能说明比较能力；这不是市场份额或效果排名。产品页面描述的是功能，不等于功能效果已经得到独立验证。

| 产品 | 官方页面展示的做法 | 职途智配现状与可借鉴之处 |
| --- | --- | --- |
| [Teal Job Matcher](https://help.tealhq.com/en/articles/12060992-using-the-job-matcher) | 可选已保存岗位、岗位库岗位或粘贴 JD；列出简历已有与缺失的关键词，并可定位到简历位置。 | 底层 ResumeForge 已有岗位分析和简历编辑；研究生实验台有命中的能力与片段，但缺少从每条岗位要求直达简历证据的完整交互。适合接通现有分析能力。 |
| [Huntr Job Match Score](https://help.huntr.co/en/articles/12241684-job-match-score) 与 [Application Packets](https://help.huntr.co/en/articles/14367332-application-hub-and-packets) | 区分必要与加分条件，展示覆盖与缺口；把一份岗位对应的定制简历、求职信和跟进材料放在一起。 | 底层已有逐条岗位要求分析、简历版本、投递记录。研究生页尚未将一个选中的岗位、证据分析、简历版本和后续状态串成一条路径；无需重新开发整套模块。 |
| [Simplify Copilot](https://help.simplify.jobs/en/articles/2415391-use-copilot-to-autofill-applications) | 根据资料填充受支持的网申字段，用户复核并自行提交。 | 底层已有网申填表功能。此能力对研究生选岗主线的新增价值有限，目前不宜重复建设。 |
| [超级简历关键词扫描器](https://www.wondercv.com/resume-keyword-scanner) | 输入职位描述并上传简历，给出关键词、缺失项与匹配分数。 | 底层已有匹配参考分。单纯增加另一套“ATS 分数”难以形成区别；研究生场景更需要解释学历、专业、科研经历和能力证据。分数不能解释为录用概率。 |

## 目前真正的缺口

1. **解析输入尚不够稳。** 本工作区对六份公开合成 PDF 试测，姓名识别 5/6、教育条数 3/6 与标注一致；这不足以代表真实研究生简历效果。研究生页能从招聘原文生成待核对草稿，但尚无独立 JD 字段准确率。参考 `docs/提交准备核对_2026-11-04.md`。
2. **研究生选岗页与底层已有能力尚未形成闭环。** `/graduate` 当前显示方向分组、理由、命中技能、证据片段、下一步问题和一条简历建议；底层岗位详情的逐条 JD 结论、简历版本及投递记录仍是另一路功能。
3. **效果尚未用独立样本证明。** 目前五份虚构画像和 14 条岗位摘要参与了规则设计，不应拿同一批样本声称准确率提升；真实试用表尚为空。

## 建议实施顺序

### P0：先把信息核对与效果验证做扎实

- 选取新增且不参与规则开发的研究生简历和招聘原文，分别记录 PDF/DOCX/扫描件解析错误、JD 硬门槛/偏好/未知字段错误、岗位来源与有效性。真人简历须获授权并留在本地私有目录。
- 对学历、毕业年份、专业、技能等影响排序的字段，显示原文和确认状态；未知或未经确认的条件不能被当成已满足或已不满足。
- 由两名独立复核者先标注，再看产品排序。至少记录硬条件误判、证据正确率和完成一次选岗所需操作；低于人工核对可靠性时优先修解析，不急着加模型。

### P1：把研究生选岗结果接到现有岗位详情与简历版本

- 在研究生页给每个岗位增加“逐项核对要求”入口：按必要条件、偏好条件、待确认问题展示招聘原文、简历原文、结论和来源链接。优先复用现有岗位分析结构，不复制第二套打分系统。
- 用户确认岗位后，能够保存岗位并从该岗位创建一份简历版本；保留岗位来源、核查日期和对应版本。投递状态由用户明确记录，不能把“保存岗位”写成“已投递”。
- 验收用一条完整操作：导入简历 → 粘贴或打开岗位 → 校对硬门槛 → 查看证据 → 保存岗位 → 建立对应简历版本。评委应能追溯每条结论的来源。

### P2：做研究生特有的经历表达辅助

- 将“科研项目、论文、实验、竞赛”的事实整理成可核对字段：本人贡献、方法或工具、可证明成果、岗位对应能力。只依据用户已确认的事实给出岗位定向表达建议，缺数字就追问，不补造。
- 复用已有简历编辑与建议采纳能力；通过真实研究生试用判断建议是否有帮助，再决定是否扩展到整份简历自动改写。

## 暂不作为本轮开发重点

- 另做一个 ATS 百分制分数、重新开发通用简历模板/模拟面试/网申填表/投递台：底层已经提供相近能力。
- 大规模抓取岗位、自动投递或承诺提高录用率：目前岗位开放状态和匹配效果尚未得到足够核验。
- 立即上 Embedding、复杂智能体或数据库迁移：先用独立样本证明现有规则的具体不足，再选择最小必要改动。

**建议下一步的最小开发任务：**先补一批独立、授权的简历与 JD 样本，做错误清单；同时在 `/graduate` 给每条岗位结果接入“逐项核对要求”的清晰入口。先做这一处集成，比增加更多泛用功能更能让产品可用、可解释，也更能体现团队在研究生场景的增量。
