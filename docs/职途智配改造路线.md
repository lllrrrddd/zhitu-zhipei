# 从 ResumeForge 基线改造成“职途智配”

## 产品定位

面向研究生的一条可核验流程：导入简历 → 逐字段确认能力画像 → 对比多条岗位 → 查看硬门槛、证据和排序理由 → 确认缺失信息并重排 → 生成一条可采纳的简历建议。底层 ResumeForge 保留第三方来源和 Apache-2.0 声明；比赛材料分别列出复用功能与团队改动。

## 试测暴露的缺口

- 页面主要入口已更名为“职途智配”，但功能组织仍偏通用求职，研究生场景不突出。
- 简历导入的本地规则在六份公开合成 PDF 上初测仅有三份识别对姓名，修复后为五份；教育条数初测 1/6、第二轮修复后 3/6 与标注一致。经历分区仍会拆错，AI 识别两份也有结构错误。
- 现有岗位分析使用模型一次生成要求—证据矩阵，参考分从结果派生。批量排序已改为硬性门槛优先，但申报表中的 Embedding 召回、研究生能力画像及目标场景评测仍需实现，不能作为已完成成果介绍。
- 本机 CPU 模型单份简历识别约 87～102 秒，单岗匹配约 88～172 秒。演示需要后台任务、进度和缓存。
- 原有岗位试测为一份本科运维简历配三条虚构 JD。现已建立 5 份虚构研究生画像、14 条来源可追溯的岗位事实摘要和作者初标，见 `evaluation/graduate_benchmark_v0/`；还缺 20～30 条目标岗位、独立复核标注及真实用户试用。
- 结构化离线基线已调用现有打分和排序函数：材料、生物、集成电路画像的 Precision@5 均为 0.20，金融画像为 0.00，暴露了通用技能词与中性分造成的误排。该基线绕过 OCR、JD 自动抽取和模型推理，不能当作产品准确率；见 `evaluation/graduate_benchmark_v0/baseline_report_2026-11-04.md`。

## 实施顺序与验收

### P0：建立研究生评测集

已自建 5 份不含真人信息的研究生画像，覆盖计算机、材料、生物、经管和集成电路，并记录 14 条有来源的岗位摘要。下一步扩至 20～30 条目标岗位，补齐来源发布日期、投递有效性与独立人工标注；标注学历门槛、技能证据、预期前 5 名和至少一个不该推荐的反例。公开合成简历用于版式测试，不代替目标场景评测。

当前可运行 `scripts/run_graduate_benchmark.py` 用同一组结构化输入重复计算参考分、排序、Recall@5、Precision@5 和 NDCG@10。该脚本只做算法回归，端到端评测仍需把原始简历和岗位文本走过实际界面。

已生成两份独立复核表，分别给未参与编写者填写，避免直接沿用作者初标。`scripts/graduate_recommendation_experiment.py` 与产品 `/graduate` 共用同一组结构化排序规则，可展示专业方向、能力依据和空结果；用户可手工录入经核对的岗位条件及来源参与排序。规则参考了同一批演示样本，下一步必须用盲审结果及新增保留样本检验，再决定是否自动处理用户自己的任意 JD。

验收：样本、标注规则、来源和人工预期可独立复核；每次改动自动产出同一批结果的对比表。

### P1：可核对的简历画像

导入弹窗已能显示逐字定位的字段片段，并区分文档文字与模型抄录；未定位字段会提示核对。下一步补齐文件页码、字段确认状态、重复教育/经历检测；用户更正后保存确认版本。PDF、DOCX、扫描件分别测，扫描件单列 OCR 成功率。

验收：用户能发现并修改本次试测中的漏姓名、重复教育、经历错分；未经确认的字段不用于硬门槛断言。

### P2：可复算的多岗排序

批量排序已实现“硬性门槛满足 → 待确认 → 不满足”的优先级，横向对比模型输出也加了同一约束。下一步把学历、年限、地点等条件改为可复算的规则判定；对项目、科研、技能与 JD 能力点做召回与重排；模型负责基于证据的解释和待确认问题。保存每项分数、权重、证据来源与算法版本。用同一评测集比较 Top-5 命中、排序质量、证据正确率及耗时。

验收：对一份研究生简历至少三条岗位能稳定排序，错误案例可定位到解析、规则、召回或解释的具体一步。

### P3：研究生求职智能体闭环

遇到研究方向、论文贡献、实习年限等缺失信息时，只追问影响排序的关键事实。用户回答并确认后重排，显示“哪条事实改变了哪条结论”。生成一条引用原文、可接受或拒绝的简历建议，并记录用户反馈。

当前研究生选岗页已允许补充事实并显示岗位分组变化；证据化建议下新增采纳/拒绝及理由输入，用户可下载包含来源、证据和时间的本地 JSON 反馈记录。它还没有形成自动汇总或真实用户试用结果。

验收：演示一次“信息缺失 → 追问 → 用户确认 → 排序更新 → 建议采纳”的完整过程；不自动编造论文、成果和数字。

### P4：参赛界面与材料

中文主标题、侧栏图标和网页 favicon 已改为“职途智配”。下一步把导入画像、岗位排序、追问重排和建议采纳组织成清晰主流程，将通用辅助功能放到次级导航。提供一份无个人信息的离线演示数据和一键复位方式。申报材料如实展示已完成模块、实测样本量、开源来源和团队新增功能。

验收：评委从打开页面到看到证据化岗位排序不超过五步；演示视频中的每个结果都能在本机复现。

## 暂缓范围

教师群体画像、就业材料核验、语音面试和 PostgreSQL 迁移等功能在核心流程验收后安排。它们在申报表中是计划能力，展示时应与已经实现的功能分开标注。
