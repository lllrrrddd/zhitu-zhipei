# 匹配分口径说明（2026-11-07）

界面上每个推荐岗位显示一个 0–100 的分数和四条横条。这份文档说明它怎么算、为什么不是"录取概率"、以及怎么复算。

## 分数构成

| 组成 | 权重 | 取值 | 依据 |
| --- | --- | --- | --- |
| 方向 | 40 | 岗位标题命中你填的目标岗位 = 100；仅属于同一方向大类 = 85；否则该岗位不会出现在结果里 | 岗位标题 + 方向词表（`job_market_match._DIRECTIONS`） |
| 技能 | 30 | 命中你给出证据的具体技能：1 项 = 33、2 项 = 67、3 项及以上 = 100；只命中 Python/SQL 这类通用工具 = 40；一项都没有 = 0 | 简历技能与项目经历原文 × 岗位要求原文（`_SKILL_TERMS`） |
| 城市 | 10 | 岗位城市包含你的意向城市 = 100，否则 0 | 岗位城市字段 |
| 入职门槛 | 20 | 校招/管培 = 100；社招但未写经验要求 = 85；写了经验要求 = 0 | 岗位类型 + 经验要求识别 |

**总分 = 四项加权和 − 经验门槛扣分**，其中经验门槛扣分在"岗位明确要求工作经验"时为 20 分，否则为 0。分数下限 0、上限 100。

举一个真实的输出（运维画像投腾讯 SRE）：

```text
方向 100 × 40% + 技能 67 × 30% + 城市 100 × 10% + 门槛 0 × 20% = 76.1
76.1 − 20（岗位要求工作经验）= 56 分
```

同一个岗位、同一份画像，任何时候算出来都是这个数——权重写死在代码里，不随结果、不随批次变化。

## 与"语义相近度"的关系

如果本机装了 `qwen3-embedding:0.6b`，系统还会对入选的十几个岗位算一次向量相似度，界面上显示为"语义相近度 X%"。

- 它**不进入**上面的分数，只用于同分时的排序（`score + 30 × 相似度`）；
- 用"语义相近度"这个说法，而不是"匹配度"，是因为向量相似只能说明"文字上像"，不能说明"这个岗位适合你"；
- 没有模型时不显示这一项，分数与排序仍然可用。

## 为什么不是录取概率

分数衡量的是"岗位写出来的要求"和"你填写的资料"之间的重合程度。它不含：竞争者数量、面试表现、名额、投递时间、HR 偏好。因此界面上不会出现"录取概率"字样，答辩时也应主动说明这一点。

## 差距清单（gaps）

分数之外，每条结果还会列出"为什么不是满分"。这些条目由后端给出结构化的 key，前端映射成中文：

| key | 含义 |
| --- | --- |
| `degree_unspecified` | 岗位原文没写学历要求，需到招聘页确认 |
| `degree_unconfirmed` | 你的资料还没确认学历 |
| `experience_required` | 岗位要求工作经验（同时触发 20 分扣分） |
| `missing_skills` | 岗位提到、但你的资料里没有证据的能力（列具体项） |
| `city_mismatch` | 工作城市不在你的意向城市 |
| `no_evidence` | 只按方向和技能名称对上，简历里找不到对应的项目或经历原文 |
| `graduation_check` | 校招岗位，需核对应届毕业时间范围 |

`no_evidence` 是这一轮新增的重点：此前"可能相关"的岗位上如果没有任何原文证据，卡片上什么都不显示，用户看到的是一个没有理由的推荐。现在这类岗位会明确写出"只有方向和技能名称对得上"。

## 复算与测试

- 计算逻辑：`backend/app/services/job_market_match.py` 的 `_score`、`_gaps`；
- 契约测试：`backend/tests/test_career_score_breakdown.py`（权重合计、分项范围、经验扣分、差距项、可复现性）；
- 前端渲染：`frontend/src/features/career/CareerResults.tsx` 的分数区块。

**注意**：分数只在"通过硬门槛过滤之后"才计算。学历不满足、届别不符的岗位根本不会进入结果列表，因此不存在"分数很低但方向错的岗位混进来"的情况。
